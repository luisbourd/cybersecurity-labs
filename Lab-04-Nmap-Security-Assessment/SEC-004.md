# SEC-004 — Network Service Exposure Assessment

**Asset:** Ubuntu VM (VirtualBox)  
**Category:** Security Configuration Review  
**Severity:** Low (provisional; depends on operational need and network reachability)  
**Status:** Investigation complete for local host; external reachability not validated  
**Date:** 2026-10-16

## Summary
During authorized local analysis, CUPS (IPP, TCP/631), Avahi (mDNS, UDP/5353), and cups-browsed were identified as running. CUPS listened only on IPv4/IPv6 loopback; Avahi bound to IPv4/IPv6 wildcard addresses. UFW reported inactive. The visible nftables ruleset was empty and the inspected iptables/ip6tables chains had ACCEPT defaults and no rules. These findings do not prove external reachability, exploitation, or compromise.

## Evidence
| Check | Result |
|---|---|
| `ss -tulpen` | CUPS: `127.0.0.1:631`, `[::1]:631`; Avahi: `0.0.0.0:5353`, `[::]:5353` |
| `systemctl is-enabled/is-active` | CUPS and Avahi enabled and active before temporary testing; cups-browsed active |
| `nmap -sS -sV -p 631 127.0.0.1` | Before: `631/tcp open ipp CUPS 2.4`; after stop: `closed` |
| `nmap -sU -p 5353 127.0.0.1` | Before: `5353/udp open|filtered`; after stop: `closed` |
| `ss` after stop | No matches for ports 631 or 5353 |
| `ufw status` | Inactive |
| `nft list ruleset` | No rules output |
| `iptables -L -n -v`, `ip6tables -L -n -v` | Displayed chains: ACCEPT policies with no listed rules |
| `ip -br addr` | VM IPv4 `10.0.2.15/24` and IPv6 addresses present |
| Restore check | CUPS, Avahi and cups-browsed active; listening sockets restored |

## Risk assessment
Avahi has a wider potential listening surface than loopback-bound CUPS. If the workstation does not need device discovery or printing, these services may create unnecessary attack surface. Actual reachability from other devices, any compensating VirtualBox NAT controls, and version-specific vulnerabilities were not validated. No malicious activity or exploitable vulnerability was established.

## Recommendations
1. Confirm printing and discovery requirements with the service owner. If unneeded, request approval to disable CUPS, cups-browsed, and Avahi, including their activation sockets, and record rollback steps.
2. Evaluate a host-firewall baseline for both IPv4 and IPv6; test allowed services before deploying rules to avoid disruptions.
3. Restrict unnecessary inbound traffic by interface, source and protocol, following least privilege. Validate from an authorized separate host and repeat local `ss`, `systemctl`, and Nmap checks.
4. Keep packages updated and check applicable security advisories; do not infer vulnerability solely from a service/version label.

## Change validation / rollback
Temporary service stops resulted in `closed` for localhost TCP/631 and UDP/5353. Units were subsequently restarted and their listening sockets reappeared. No persistent disabling or host-firewall change was applied in this lab.

## Final disposition
**Local assessment documented; remediation recommended only if operationally justified and approved.** Separate-host reachability is an open validation item.
